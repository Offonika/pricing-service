# Workflow: pricing-strategies

Использовать для формул, ограничений маржи, ориентиров по конкурентам, специальных
режимов и объяснимости рекомендованной цены.

## Контекст

- Канонический документ — профильный раздел `docs/price-strategies.md` или spec,
  возвращённый root-router.
- Основные пути: `app/services/pricing_strategies/`, вызывающие services, schemas и
  unit tests.
- Сверить единицы измерения, округление, валюту, налоги, fallback и порядок правил.

## Действия

1. Перевести правило в явные входы, формулу, ограничения и ожидаемую причину решения.
2. Сохранить детерминированность для одинаковых входов.
3. Возвращать структурированные reason/flags, пригодные для API, отчёта и Telegram.
4. Покрыть границы: минимальная маржа, отсутствие конкурента, экстремальные значения,
   округление и конфликт правил.
5. При изменении сервисного контракта подключить `pricing-backend` workflow.

## Ограничения и проверки

- Не менять формулу только по предположению, если canonical rule неоднозначен.
- Не реализовывать импорт или внешнюю интеграцию внутри стратегии.
- Запустить unit tests стратегий, regression tests вызывающего сервиса, Ruff и Black.
