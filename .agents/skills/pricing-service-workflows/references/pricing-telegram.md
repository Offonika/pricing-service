# Workflow: pricing-telegram

Использовать для Telegram-команд, диалогов, прав доступа, сообщений и интеграции бота
с backend API.

## Контекст

- Основные пути: `app/telegram/`, связанные `app/api/`, services и tests.
- Читать профильный PRD/spec/runbook, возвращённый root-router.
- Найти handler, callback data, backend client и тесты нужного сценария.

## Действия

1. Описать happy path, отказ авторизации, пустой результат, timeout и повтор команды.
2. Держать состояние в сервисе/БД, а Telegram использовать как UX и канал доставки.
3. Важное действие делать идемпотентным и подтверждаемым пользователем.
4. Новый endpoint оформлять через `pricing-backend`, а новую команду отражать в docs.
5. Логировать технический идентификатор и исход без токенов и текста с секретами.

## Ограничения и проверки

- Не хранить bot token в коде и не выполнять live-отправку без явного разрешения.
- Не дублировать критичную бизнес-логику в handler.
- Проверить handlers/callbacks на mocked dev API, авторизацию и ошибки; затем Ruff,
  Black и профильные pytest.
