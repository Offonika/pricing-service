# Workflow: pricing-universal

Использовать только для небольшой локальной правки без явного профильного владельца:
опечатки, узкий regression fix, небольшой тест или безопасная механическая правка.

## Контекст

- Взять минимальный контекст из root-router и найти точный участок через `rg`.
- Проверить ближайший тест и локальные инструкции для затронутого каталога.
- Если затронут API, данные, формула, инфраструктура или внешний side effect, перейти
  к профильному workflow вместо universal.

## Действия

1. Сформулировать узкую границу изменения и не расширять рефакторинг попутно.
2. Прочитать исходник и тест до правки.
3. Добавить или обновить regression test, если меняется поведение.
4. Запустить минимальную профильную проверку и общий quality gate по необходимости.

## Ограничения и проверки

- Не использовать как обход архитектурного решения или согласования контракта.
- Не принимать неоднозначное бизнес-решение без canonical rule.
- В отчёте явно указать предположения и незапущенные проверки.
