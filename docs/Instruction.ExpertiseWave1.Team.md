# Инструкция для команды: контур «Экспертиза» Wave 1

Дата актуализации: 12.04.2026

## 1. Что изменилось

Теперь экспертизы работают в новом контуре:

- `1С` остается системой учета документа `Экспертиза`;
- backend автоматически синхронизирует кейс в `Bitrix24`;
- в `Bitrix24` создается карточка smart-process `Экспертиза`;
- по каждой экспертизе создается связанная папка в `Bitrix Disk`;
- после принятия решения автоматически создается задача на уведомление клиента;
- стадия `В работе ОКК` теперь может наступать автоматически по нормативу доставки, без ручного перетаскивания карточки;
- если уведомление клиента затягивается, система сама присылает напоминания и эскалации.

Старый чат `Экспертиза` используется только как архив. Новые рабочие материалы и комментарии по кейсу туда переносить не нужно.

## 2. Где смотреть экспертизы

Работать нужно в двух местах:

- `Bitrix24 CRM -> smart-process "Экспертиза"` — карточка кейса;
- `Bitrix Disk -> Отдел контроля качества -> Экспертиза` — папки и файлы по кейсам.

В карточке экспертизы есть ссылка на папку `Bitrix Disk` конкретного кейса.

## 3. Какой теперь рабочий порядок

### Шаг 1. Экспертиза создается в `1С`

- документ `Экспертиза` заводится как обычно в `1С`;
- вручную дублировать карточку в `Bitrix24` не нужно.

Ожидание:

- в течение нескольких минут кейс появляется в smart-process `Экспертиза`;
- автоматически создается папка кейса в `Bitrix Disk`.
- сначала карточка обычно появляется в стадии `Создано`.

### Шаг 2. Кейс попадает в `В работе ОКК`

Теперь эта стадия работает так:

- кейс сначала приходит в `Создано`;
- система считает норматив доставки до `ОКК`;
- когда норматив доставки истекает, backend автоматически переводит карточку в `В работе ОКК`;
- ручной перевод менеджером `ОКК` больше не обязателен для основного сценария.

### Шаг 3. `ОКК` проводит экспертизу

В карточке будут видны:

- номер экспертизы;
- код реализации `1С`;
- код заказа покупателя `1С`, если он есть;
- подразделение;
- клиент и телефон;
- решение;
- текущий статус;
- ссылка на папку кейса.

### Шаг 4. Материалы по кейсу складываются в папку `Bitrix Disk`

Фото, видео, сканы и другие материалы нужно хранить в папке кейса в `Bitrix Disk`.

Новый стандарт:

- материалы прикладываем в папку кейса;
- не используем старый чат как основное место хранения;
- не храним рабочие материалы только локально на компьютере.

### Шаг 5. После решения система ставит задачу на уведомление клиента

Когда решение по экспертизе зафиксировано:

- система автоматически создает одну задачу `Уведомить клиента по экспертизе ...`;
- постановщик задачи — система;
- основной исполнитель — руководитель подразделения, из которого оформлена экспертиза;
- соисполнители — остальные активные сотрудники этого подразделения;
- наблюдатели — `ОКК`;
- в задаче уже есть номер экспертизы, клиент, телефон, решение и срок уведомления.

Если у подразделения не назначен руководитель в оргструктуре `Bitrix24`, задача уходит на fallback-координатора `ОКК`, но сотрудники подразделения все равно остаются соисполнителями.

### Шаг 6. Подразделение уведомляет клиента

Подразделение-инициатор должно:

- связаться с клиентом;
- сообщить результат экспертизы;
- при необходимости оставить комментарий в задаче.

Если по кейсу пришло напоминание или эскалация, это значит, что срок уведомления клиента уже вышел или близок к просрочке.

### Шаг 7. Факт уведомления клиента фиксируется в контуре

Для `Wave 1` важно различать:

- задача на уведомление клиента создается автоматически;
- закрытие задачи должно происходить только после подтверждения факта уведомления клиента в контуре.

Поэтому:

- не закрывайте notify-task просто «для порядка», если клиент еще не уведомлен;
- сначала должен быть подтвержден факт уведомления клиента по действующему внутреннему порядку;
- после этого задача закрывается автоматически.

Если в вашем процессе подтверждение уведомления делает координатор `ОКК`, передайте ему информацию сразу после контакта с клиентом.

## 4. Что означают статусы

- `Новая` — кейс только появился в контуре;
- `Создано` — кейс только появился в контуре и еще находится в этапе доставки до `ОКК`;
- `В работе ОКК` — кейс нормативно поступил в `ОКК` и находится в рабочей фазе;
- `На экспертизе` — идет проверка / разбор случая;
- `Решение готово` — решение принято, нужно уведомить клиента;
- `Клиент уведомлен` — подразделение подтвердило, что клиент оповещен;
- `Возвращено в подразделение` — кейс завершен по бизнес-процессу;
- `Ручная проверка` — кейс требует отдельного разбора.

Если названия в интерфейсе чуть отличаются, ориентируйтесь на смысл статуса, а не на технический код.

## 5. Что делает система автоматически

Система сама:

- подтягивает экспертизы из `1С`;
- создает и обновляет карточки в `Bitrix24`;
- создает папки кейсов в `Bitrix Disk`;
- считает срок доставки до `ОКК` и срок ответа `ОКК` в календарных днях;
- автоматически переводит кейс в `В работе ОКК` после истечения норматива доставки;
- создает задачу на уведомление клиента после принятия решения;
- присылает будильники по сроку ответа `ОКК`: для Москвы через 2/4/12 дней, для остальных через 13/15/23 дня, с ежедневным повтором до решения;
- делает эскалацию, если клиент долго не уведомлен.

Плановые фоновые процессы:

- sync `1С -> backend -> Bitrix24` — каждые 5 минут;
- проверка будильников и эскалаций — каждые 15 минут.

## 6. Что команде делать нельзя

Не нужно:

- вручную создавать дубли карточек экспертиз;
- вручную создавать вторую задачу на уведомление клиента по тому же кейсу;
- хранить новые файлы только в старом чате `Экспертиза`;
- переименовывать или переносить системные папки кейсов в `Bitrix Disk`;
- удалять технические поля из карточки, если они кажутся лишними;
- закрывать notify-task до фактического уведомления клиента.

## 7. Когда надо сообщить о проблеме

Напишите координатору `ОКК` или техническому ответственному, если:

- экспертиза есть в `1С`, но не появилась в `Bitrix24`;
- у кейса нет папки `Bitrix Disk`;
- после решения не создалась задача на уведомление клиента;
- пришла эскалация, но клиент уже был уведомлен;
- карточка выглядит задвоенной;
- в папке или карточке явно не хватает данных.

## 8. Короткий чек-лист для сотрудников

- Экспертизу вручную в `Bitrix24` не создаем.
- Все новые материалы кладем в папку кейса в `Bitrix Disk`.
- После решения проверяем, что появилась задача на уведомление клиента.
- Клиента уведомляет подразделение-инициатор.
- Основной исполнитель задачи — руководитель подразделения или fallback-координатор, если руководитель не настроен в оргструктуре.
- Notify-task не закрываем раньше фактического уведомления клиента.
- Если что-то не создалось автоматически, сразу эскалируем.

## 9. Для руководителя / координатора

Контрольные точки:

- все новые кейсы должны автоматически попадать в smart-process;
- по кейсам со статусом `Решение готово` должна быть notify-task;
- по просроченным кейсам должны приходить напоминания;
- материалы по кейсу должны лежать в `Bitrix Disk`, а не только в чате.

Если требуется доработка процесса, фиксируйте ее как отдельное предложение, а не обходите текущий контур ручными костылями.
