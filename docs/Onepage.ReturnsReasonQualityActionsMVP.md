# Onepage: Контур причин возврата, ОКК и управленческих действий

Статус: draft на согласование
Дата: 2026-06-21

## 1. Проблема

Возвраты сейчас можно оформить в `1С`, но управленческий цикл вокруг причины
возврата не замкнут.

Есть несколько разрывов:

- старший по продажам не получает рабочую выжимку по тому, что происходит с
  возвратами и что нужно сделать;
- причина возврата в строке документа есть, но ее нужно привести к форме,
  пригодной для анализа и KPI;
- `ОКК` / отдел брака часто фиксирует вывод по товару, но вывод не всегда
  превращается в действие для продаж, закупки или поставщика;
- закупщик должен выступать переговорщиком с поставщиком по проблемным партиям,
  а не просто получать поздний факт брака;
- руководитель направления должен видеть не только количество возвратов, а
  качество выполнения действий ответственными.

Цель: не просто учитывать возврат, а снижать повторяемость возвратов через
причину, подтверждение, действие и контроль результата.

## 2. Принцип решения

Базовая цепочка:

```text
Возврат -> первичная причина -> подтверждение / экспертиза -> действие -> KPI
```

`1С` остается источником учетного факта: документ возврата, товар, партия,
количество, сумма, причина, экспертиза и связанные документы.

Внешний контур / Bitrix24 должен вести управленческие действия:

- задачи старшему по продажам;
- задачи `ОКК` / отделу брака;
- задачи закупщику для переговоров с поставщиком;
- отчет руководителю направления по выполнению действий.

## 3. Что получает старший по продажам

Старшему нужна не выгрузка, а регулярная задача на разбор.

Минимальная выжимка в задаче:

- период;
- количество и сумма возвратов;
- топ причин по сумме и количеству;
- топ сотрудников / точек с ростом подтвержденных возвратов по ошибке продажи;
- спорные возвраты, которые нельзя включать в KPI до подтверждения;
- 3-5 приоритетных кейсов для разбора;
- ожидаемое действие: обучение, проверка скрипта, разговор с менеджером,
  корректировка инструкции или отметка "ошибка продажи не подтверждена".

Результат задачи старшего:

- причина подтверждена или снята;
- действие назначено;
- действие выполнено или просрочено;
- повторная проверка назначена, если проблема системная.

## 4. Что делает ОКК / отдел брака

`ОКК` должен давать не только вывод "брак / не брак", а решение, что делать с
товаром и кому передать следующий шаг.

Приоритетный порядок:

1. Проверить, можно ли быстро и экономически разумно восстановить товар.
2. Если восстановление невозможно или невыгодно, подготовить аргументированный
   кейс закупщику для переговоров с поставщиком.
3. Закупщик как переговорщик запрашивает у поставщика решение: возврат, замена,
   компенсация, скидка / кредит-нота или официальный отказ.
4. Если поставщик отказал или решение невыгодно, выбрать внутренний исход:
   уценка, списание, оставить как брак, вернуть в продажу после восстановления
   или вынести партию на отдельный разбор.

В каждом кейсе `ОКК` должен фиксировать:

- товар / партию / поставщика, если доступны;
- причину обращения;
- результат проверки;
- можно ли продавать товар дальше;
- нужно ли остановить партию;
- нужна ли задача закупщику;
- какие доказательства приложены: фото, комментарий, заключение, история
  повторов.

## 5. Что делает закупщик

Закупщик отвечает не за сам факт брака, а за коммерческое решение с поставщиком.

В задаче закупщику должны быть:

- товар и партия / поставка;
- количество случаев;
- сумма риска;
- заключение `ОКК`;
- фото / доказательства;
- желаемый исход;
- срок ответа поставщика;
- итог переговоров.

Допустимые итоги:

- поставщик принимает возврат;
- поставщик меняет товар;
- поставщик дает компенсацию;
- поставщик дает скидку / кредит-ноту;
- поставщик отказал с причиной;
- требуется решение руководителя направления.

## 6. Что видит руководитель направления

Руководитель должен видеть отчет не о "количестве возвратов вообще", а о
выполнении управленческих действий.

Минимальный отчет:

- возвратов за период: количество и сумма;
- сколько причин подтверждено;
- сколько причин спорные / ждут экспертизу;
- сколько задач старшим по продажам создано;
- сколько действий старших выполнено / просрочено;
- сколько задач `ОКК` выполнено / просрочено;
- сколько кейсов передано закупщику;
- сколько поставщиков дали решение;
- повторные возвраты по тем же товарам / причинам;
- топ 5 проблемных товаров / партий / поставщиков.

KPI / премия руководителя направления должны зависеть не от голого процента
возвратов, а от качества реакции:

- причины не висят без подтверждения;
- спорные кейсы не залеживаются;
- `ОКК` дает применимые решения;
- старшие по продажам выполняют корректирующие действия;
- закупщик закрывает переговоры с поставщиком в срок;
- повторяемость по тем же причинам снижается.

## 7. MVP

Первый запуск без тяжелой переделки:

1. Выгрузить возвраты за период из `1С` по строкам.
2. Посчитать заполненность и качество текущей колонки `Причина возврата`.
3. Сделать регулярную задачу старшему по продажам с короткой выжимкой.
4. По причинам `брак / качество / экспертиза` создать отдельный список кейсов
   для `ОКК`.
5. Для подтвержденных проблем партии создавать задачу закупщику.
6. Раз в неделю собирать отчет руководителю направления по выполненным и
   просроченным действиям.

## 8. Не входит в первый шаг

- автоматическое наказание менеджеров;
- включение спорных причин в KPI;
- полная роботизация `ОКК`;
- автоматический возврат поставщику без переговоров закупщика;
- замена контура экспертиз и качества внутри старой `1С`.

## 9. На согласование

Нужно утвердить:

- периодичность задачи старшему по продажам: ежедневно или еженедельно;
- список причин, которые относятся к продажам;
- список причин, которые уходят в `ОКК`;
- порог, после которого кейс передается закупщику;
- срок ответа закупщика по поставщику;
- кто получает отчет руководителя направления;
- какие показатели можно включать в премиальную часть, а какие пока только
  наблюдать.
