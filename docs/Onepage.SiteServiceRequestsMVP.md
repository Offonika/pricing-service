# Onepage v0.4 — «Сервисные обращения сайта»

Дата: `22.08.2026`

Статус: проект концепции для обсуждения командой.

Связанная задача: Bitrix24 №3223.

## 1. Зачем нужен этот процесс

Клиенты уже могут создавать тикеты в личном кабинете сайта, но эти обращения не
попадают в понятную рабочую очередь. Из-за этого обращение формально существует,
а сотрудник может его не увидеть, не взять в работу и не ответить клиенту.

На 20 августа 2026 года в старом модуле накопилось:

- 740 тикетов всего;
- 587 открытых тикетов;
- 347 тикетов, созданных в 2026 году;
- ни одного зарегистрированного ответа техподдержки за 2026 год.

Цель первой версии — не заменить личный кабинет или переписку с клиентом, а
подключить их к действующей рабочей системе компании.

## 2. Главная рекомендация

Новый смарт-процесс создавать не нужно.

В Bitrix24 уже существует процесс **«Рекламации сайта / Браки сайта»**. В нём
есть отдельная очередь **«Рабочие рекламации»**, карточка клиента и заказа,
вложения, ответственный, сроки, варианты возврата и связь с экспертизой.

Именно его предлагается использовать как основное рабочее место для новых
тикетов сайта. Команда согласовала рабочее название **«Сервисные обращения
сайта»**. Переименование живого смарт-процесса выполняется отдельно после
подготовки пилота; в этом документе старое название сохраняется только там, где
описывается текущее состояние Bitrix24.

Смарт-процесс **«Экспертиза»** остаётся отдельным процессом. В него попадают
только обращения, по которым товар действительно нужно передать на проверку в
ОКК и оформить экспертизу в 1С.

## 3. Что уже есть и как это использовать

| Что уже есть | Для чего использовать |
| --- | --- |
| Тикеты в личном кабинете сайта | Приём обращения, переписка, файлы и показ ответа клиенту |
| «Рекламации сайта / Браки сайта» | Главная рабочая очередь сотрудников по новым обращениям |
| «Экспертиза» | Проверка товара в ОКК, решение по качеству и контроль уведомления клиента |
| CRM | Поиск существующего клиента, компании, заказа или сделки; клиентский чат может быть связан с обычной CRM-карточкой |
| Задачи Bitrix24 | Отдельные действия: связаться с клиентом, оформить возврат, согласовать деньги |
| Архив старых браков сайта | Поиск похожих случаев и истории решений |
| Открытая линия | Живой чат с клиентом; связь с обычной CRM включена, но чат не заменяет учёт сервисного обращения |
| ChatApp в обычной CRM | Связанный клиентский диалог можно открывать из карточки контакта, компании, лида или сделки |
| ChatApp в смарт-процессе | Вкладки для действующего процесса рекламаций доступны, но сейчас не включены |
| Локальное приложение Bitrix24 | Может добавить действие к конкретному сообщению и передать его в рабочую очередь; такого действия сейчас ещё нет |

## 4. Какие сообщения превращать в обращения

### Что сейчас происходит с клиентскими чатами в обычной CRM

Обычная CRM-карточка клиента и карточка сервисного обращения — это два разных
места.

На живом портале у единственной активной Открытой линии включена связь с CRM и
поиск существующего клиента. Поэтому ожидаемое штатное поведение такое:

- если клиент уже найден, его внешний диалог ChatApp или Открытой линии
  привязывается к подходящей CRM-карточке контакта, компании, лида или сделки;
- из CRM-карточки можно открыть связанный чат и посмотреть переписку;
- каждое сообщение не копируется в отдельное поле или отдельный комментарий
  карточки — в карточке хранится связь с диалогом;
- если клиент не найден, текущая настройка Открытой линии создаёт продажный лид.

Для пилота это текущее правило разделяется по теме обращения: новый клиент с
гарантийным или сервисным вопросом получает контакт и сервисное обращение без
продажного лида. Продажный лид создаётся только по вопросу покупки.

Это относится только к внешней клиентской переписке, пришедшей через ChatApp или
Открытую линию. Сообщения из внутренних региональных чатов магазинов, чатов
«Сайт MASTER-MOBILE.RU», «Браки сайт», ОКК и «Экспертиза» автоматически в
карточках контактов и компаний не появляются и остаются в исходных чатах.

Настройка связи с CRM подтверждена, но её фактическая работа пока не подтверждена
на живом примере: среди последних проверенных лидов и контактов не найден источник
ChatApp, а у текущего оператора не найден активный диалог Открытой линии. Поэтому
до запуска нужен контрольный тест с одним известным и одним новым клиентом.

Автоматически превращать в обращения все сообщения из всех чатов нельзя. В
региональных чатах одновременно обсуждаются заказы, оплаты, доставка, возвраты,
качество и внутренние вопросы. Большинство сообщений не являются сервисным
обращением клиента.

Для первой версии предлагается такое простое правило:

| Откуда пришло сообщение | Что делать |
| --- | --- |
| Тикет в личном кабинете сайта | Всегда автоматически создавать или обновлять обращение |
| Клиентский чат ChatApp или Открытая линия | Создавать обращение после выбора клиентом темы «Гарантия / возврат» либо после явного действия сотрудника |
| Региональный внутренний чат магазина | Подключить на втором этапе; в пилоте новые карточки из таких чатов не создавать |
| Чат ОКК или «Экспертиза» | Обновлять уже связанное обращение; новое обращение автоматически не создавать |
| Остальные сообщения | Оставлять в исходном чате без новой карточки |

Для ручного отбора сотрудник открывает меню **«...»** у конкретного сообщения и
выбирает действие **«Создать сервисное обращение»**. Затем система показывает
короткую проверку данных, переносит текст и вложения, запоминает исходный чат и
магазин, ищет клиента и заказ и создаёт карточку в процессе «Рекламации сайта /
Браки сайта». Если такое обращение уже есть, открывается существующая карточка,
а сообщение добавляется в её историю.

Само меню сообщения уже предусмотрено Bitrix24, и живой портал поддерживает
подключение к нему своего действия. Но пункт «Создать сервисное обращение» и его
обработчик ещё нужно сделать в локальном приложении.

Отдельно уже существует штатная настройка ChatApp для этого смарт-процесса. На
пилоте вкладки **ChatApp** и **ChatApp Dialog** включаются для онлайн-отдела,
чтобы сотрудник мог работать с клиентской перепиской так же, как в сделке. Этот
переключатель не создаёт карточку из сообщения — карточка должна быть создана
автоматически из тикета либо явным действием сотрудника.

Официальное подтверждение возможностей:

- [действие в меню конкретного сообщения Bitrix24](https://apidocs.bitrix24.ru/api-reference/widgets/im/context-menu.html);
- [вкладки ChatApp в смарт-процессах](https://help.chatapp.online/kak-vstroit-vkladku-chatapp-v-smart-proczessy-bitrix24/).

## 5. Как должен идти новый тикет

1. Клиент создаёт тикет в личном кабинете сайта и прикладывает необходимые файлы.
2. Обращение автоматически появляется в очереди «Рабочие рекламации».
3. Система находит существующего клиента и его заказ. Новый продажный лид не
   создаётся.
4. Обращение получает ответственного и срок первого ответа.
5. Ответственный разбирается, что требуется клиенту.
6. Обращение направляется по одной из понятных веток:
   - консультация или уточнение;
   - замена товара;
   - возврат денег;
   - доставка или возврат товара;
   - экспертиза в ОКК;
   - другой согласованный вариант решения.
7. Решение и ответ сотрудника возвращаются в тикет сайта, чтобы клиент увидел их
   в личном кабинете.
8. Обращение закрывается только после ответа клиенту и фиксации результата.

## 6. Как связать обращение с экспертизой

Не каждое сервисное обращение является экспертизой.

Если экспертиза не нужна, обращение полностью проходит внутри рабочей очереди
рекламаций.

Если экспертиза нужна:

1. В обращении фиксируется решение «Нужна экспертиза».
2. Экспертиза оформляется по действующему порядку в 1С.
3. Существующий процесс автоматически создаёт карточку «Экспертиза» в Bitrix24.
4. Обращение и экспертиза связываются между собой.
5. В обращении видны статус экспертизы, решение ОКК и следующий шаг.
6. После решения ОКК клиент получает ответ через исходный тикет сайта.

Так ОКК не превращается в общую техподдержку, а занимается только теми случаями,
где действительно требуется проверка товара.

## 7. Простая рабочая очередь

В уже созданном процессе есть почти подходящий маршрут:

- **Новая** — обращение поступило;
- **Разобраться** — сотрудник уточняет заказ, проблему и ожидание клиента;
- **Ожидаем клиента / товар** — не хватает информации или требуется передача товара;
- **Нужна экспертиза** — принято решение оформить проверку в ОКК;
- **Связано с экспертизой** — экспертиза создана и связана с обращением;
- **Возврат денег / решение** — согласуется итог для клиента;
- **Закрыто** — клиент получил ответ, результат зафиксирован.

Для первой версии достаточно проверить названия и добавить понятное правило:
карточку нельзя закрывать, пока клиенту не отправлен ответ через сайт.

## 8. Кто за что отвечает

- **Первая линия пилота — Анна Гиря и Ариф Рахманов.** Отдельный график дежурств
  для пилота не создаётся. Система определяет, кто находится на работе, по
  открытой рабочей смене в Bitrix, а не по статусу «онлайн» или плановому графику.
  Если смена открыта у одного сотрудника, обращение назначается ему; если у обоих —
  обращения распределяются по очереди. Если смена не открыта ни у одного,
  обращение остаётся в стадии «Новая» до начала ближайшей смены.
- **Тимур Тибилов, руководитель онлайн-магазина** — получает обращение, если первая
  линия не взяла его в работу или не ответила в установленный срок. Он является
  резервным ответственным на период пилота.
- **ОКК** — подключается только к экспертизам, спорным случаям качества и решениям,
  требующим оценки товара.
- **Логистика** — подключается, когда товар нужно забрать, доставить или отследить.
- **Александра Живых, аналитик по платежам (эквайринг)** — оформляет возвраты. На
  период пилота для неё не устанавливается отдельный денежный лимит: она может
  принимать все денежные решения по сервисным обращениям.
- **Система** — подтверждает, что ответ появился в личном кабинете клиента. Пока
  автоматическое подтверждение не реализовано, это вручную проверяет сотрудник
  первой линии перед закрытием обращения.

Срок первого ответа — до **4 рабочих часов**. Обращение, пришедшее вне рабочего
времени, получает первый ответ до **12:00 следующего рабочего дня**. Отдельный
режим «срочно» со сроком ответа в один час в пилоте не используется.

## 9. Что делать со старыми 587 обращениями

Их не нужно автоматически превращать в 587 новых задач или карточек.

Сначала нужен пробный разбор без изменений:

- сколько обращений всё ещё актуальны;
- сколько уже фактически решены;
- где требуется связаться с клиентом;
- где действительно нужна экспертиза;
- где есть дубли;
- какие обращения можно закрыть после ручной проверки.

После отчёта команда отдельно решит, какую часть истории переносить в рабочую
очередь. Старые обращения должны оставаться доступными для поиска независимо от
этого решения.

## 10. Что входит в первую версию

- новые тикеты сайта автоматически попадают в рабочую очередь;
- пилот проводится на обращениях с сайта силами онлайн-отдела;
- сообщения из клиентских чатов попадают в очередь только после явного выбора
  сотрудника или клиентом сервисной темы;
- региональные чаты и руководители магазинов подключаются только на втором этапе;
- сохраняются переписка и вложения;
- находятся существующие клиент и заказ;
- назначаются ответственный, резервный сотрудник и срок реакции;
- повторное сообщение обновляет существующее обращение, а не создаёт дубль;
- на пилоте проверяется, что клиентский диалог действительно открывается из
  обычной CRM-карточки контакта или компании;
- на пилоте для онлайн-отдела включаются штатные вкладки ChatApp в карточке
  обращения;
- при необходимости обращение связывается с экспертизой;
- сотрудник отвечает из рабочего процесса, а клиент видит ответ на сайте;
- руководитель видит открытые и просроченные обращения.

## 11. Что пока не входит

- массовое автоматическое создание карточек по всем старым тикетам;
- автоматическое превращение всех сообщений из всех чатов в обращения;
- автоматическое распознавание свободного текста без подтверждения сотрудника;
- превращение каждого обращения в экспертизу;
- создание продажных лидов по гарантийным вопросам;
- автоматический перенос всей истории всех открытых линий в карточки;
- замена документов и учётных решений 1С;
- автоматическое решение спорных денежных и гарантийных случаев без сотрудника.

## 12. Как поймём, что первая версия работает

- новый тикет виден сотрудникам в течение нескольких минут;
- в согласованных чатах сотрудник может создать обращение из выбранного сообщения;
- текст, вложения, исходный чат и магазин попадают в карточку без перепечатывания;
- сообщения без явного выбора не создают лишние карточки;
- внешний диалог известного клиента открывается из его обычной CRM-карточки;
- внутренние чаты сотрудников не попадают в историю контакта или компании;
- у обращения есть ответственный и срок реакции;
- клиент и заказ связаны без нового продажного лида;
- повторное сообщение не создаёт дубль;
- если нужна экспертиза, она связана с обращением и не создаётся вручную второй раз;
- сотрудник видит всю историю и файлы;
- клиент видит ответ и актуальный статус в личном кабинете;
- руководитель видит просрочки и обращения без ответственного.

## 13. Что осталось проверить перед запуском

- проверить на тестовых обращениях все три варианта назначения по рабочей смене
  Bitrix: работает Анна, работает Ариф, работают оба сотрудника;
- на одном известном и одном новом клиенте проверить связь ChatApp с обычной
  CRM-карточкой, создание сервисного обращения, файлы и отсутствие продажного
  лида по сервисной теме;
- проверить автоматическое подтверждение появления ответа в личном кабинете;
- после пилота отдельно принять решение о составе региональных чатов и сотрудниках
  магазинов для второго этапа.
