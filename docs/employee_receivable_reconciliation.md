## Что именно оказалось причиной

1. Основная причина оказалась не в текущих движениях, а в попытке реконструировать `opening` из внутренних регистров 1С.
2. Для employee/buyer-кейсов сводная `Ведомость по взаиморасчетам` и наши SQL-реконструкции не были эквивалентны.
3. Загрузка `начальных остатков` напрямую из 1С-файла устранила этот класс ошибок.
4. Расследование stale/duplicate/order84 было полезно для локализации, но для acceptance правильным решением оказался импорт фактического opening из 1С.

## Что проверять в Power BI

1. Таблица `ДебиторкаНачальныеОстатки`
- фильтр по `Контрагент`
- фильтр по `ВидДоговора = С покупателем`
- сверка `НачальныйОстаток` по договорам

2. Таблица `ДебиторкаСверка1С`
- использовать для буквальной сверки с выгрузкой 1С, если в отчёте есть отрицательные строки
- смотреть `signed_balance`, а не `current_balance`

3. Таблица `ДебиторкаДоговоры`
- фильтр по `Контрагент`
- фильтр по `СлойРасчета`
- сверка договорного остатка и хвостов

4. Таблица `ДебиторкаТекущая`
- текущий остаток сотрудника на выбранную дату

## Следующий приоритет

1. Не трогать live 1С тяжелыми запросами
2. Дальше сверять через выгрузки и Power BI
3. Для acceptance по сотрудникам считать исторический opening-контур закрытым
4. Дальше сверять уже текущие остатки и движения после `2025-01-01`, а не пытаться снова реконструировать opening из внутренних слоев 1С
