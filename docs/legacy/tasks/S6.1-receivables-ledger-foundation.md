# S6.1 — Модель данных и загрузка истории взаиморасчётов для дебиторки

## Цель
Подготовить на сервере `A` полный расчётный фундамент для дебиторской задолженности: историю событий взаиморасчётов, историю ответственных менеджеров и базовые snapshots.

## Что нужно сделать
- Спроектировать сущности для ledger-событий дебиторки:
  - реализация;
  - оплата;
  - возврат;
  - корректировка долга;
  - взаимозачёт;
  - смена ответственного менеджера.
- Добавить хранение истории ответственности менеджеров по контрагенту.
- Реализовать импорт / sync из 1С / TopControl в нормализованный ledger.
- Подготовить snapshots текущего баланса по контрагентам на дату.
- Сохранить traceability до исходных документов: тип, номер, дата, ссылка/внешний id.
- Зафиксировать допущения по маппингу контрагентов и менеджеров в документации.

## Артефакты/файлы
- SQLAlchemy-модели / Alembic-миграции под ledger и историю ответственности.
- Сервисы sync/import для взаиморасчётов.
- Тесты на загрузку и идемпотентный повторный sync.
- Обновления `docs/architecture.md` и `docs/TechDesign.ManagementControlTower.md` при необходимости.

## Definition of Done
- В БД есть нормализованный журнал событий взаиморасчётов.
- Для любого долга можно восстановить цепочку документов.
- История ответственных менеджеров хранится отдельно от текущего состояния.
- Повторный импорт не создаёт дублей.
- Есть тесты на базовые сценарии и граничные случаи.
