# Order Flow Context

В этой папке лежат исходные контекстные материалы по текущему и целевому процессу заказов/возвратов.

Файлы:

- `AsIs_orders_returns_current_process.docx`
  - текущее состояние процесса заказов, возвратов, ролей и ограничений в `1С УТ 10.3`;
  - полезно как As-Is источник перед проектированием новых правил.
- `ONEPAGE_ToBe_orders_returns_1C_UT10_site_B24.docx`
  - целевая To-Be концепция по заказам, возвратам, сайту и `Bitrix24`;
  - полезно как управленческий one-pager и исходник для техдизайна.
- `AsIs_ToBe_Roadmap_2026-04-02.md`
  - связка `As-Is -> To-Be -> backlog Bitrix24 -> roadmap внедрения`;
  - основная точка входа для быстрого понимания контекста по проекту `Управление товародвижениями`.
- `site-order-rtu-process-context-2026-05-03.md`
  - актуальный контекст возврата к To-Be по заказам сайта после примера `211793`;
  - фиксирует, почему прежний внешний статусный слой не устраняет первопричину,
    если внутри `1С` сохраняются ранние `РТУ`, перемещения на склад `Сайт`,
    минусовые остатки и ручные возвраты.
- `site-order-1c-process-tz-2026-05-03.md`
  - ТЗ для разработчиков `1С` и сайта по исправлению процесса интернет-заказов;
  - фиксирует реквизиты, статусы, правила `РТУ`, обмен `CommerceML`, SMS,
    контрольные отчеты и приемочные сценарии.
- `onec-site-order-process-tz-2026-05-03.md`
  - отдельное ТЗ только для 1С-разработчика;
  - фокус на объектах `1С УТ 10.3`, реквизитах `Заказа покупателя`, загрузке
    `CommerceML`, правилах `РТУ`, задачах, SMS, регламентах и отчетах.
- `onec-site-order-wave1-tz-2026-05-03.md`
  - отдельное ТЗ Wave 1 на согласование;
  - фиксирует минимальную 1С-доработку без ранних `РТУ`: реквизиты,
    загрузку сайта, правила фактической `РТУ`, обеспечение и приемку пилота.
- `ut103-site-order-wave1-work-report-2026-05-06.md`
  - отчет по выполненным работам и тестам Wave 1 в тестовой базе
    `Ekama_Test_Arsen`;
  - фиксирует реализованные метаданные, обмен с тестовым сайтом, частичную
    проверку `РТУ`, исправленные ошибки и открытые вопросы перед финальной
    приемкой.
- `ut103-site-order-wave1-module-sync-diagnostic-2026-05-06.md`
  - диагностика текущего блокера `РТУ` после handoff;
  - подтверждает SQL-метаданные Wave 1 в `Ekama_Test_Arsen`, фиксирует, что
    локальная `.local/1c-config` не является актуальным Wave 1-комплектом, и
    отделяет проверку метаданных от проверки экспортной функции общего модуля
    `осиПривилегированный`.
- `ut103-wave1-next-chat-context-2026-05-06.md`
  - handoff-контекст для продолжения разработки Wave 1 в новом чате;
  - содержит текущее состояние, блокер по общему модулю, список открытых
    вопросов, следующие действия и готовый промпт для нового чата.
- `onec-tzp-wave1-tz-2026-05-03.md`
  - отдельное ТЗ Wave 1 на доработку внешней обработки `ТЗП`;
  - фиксирует перевод сборки на `Заказ покупателя`, блокировку ранней `РТУ`
    из `ТЗП`, переходную очередь старых `РТУ` и приемочные сценарии.
- `ut103-tzp-wave1-codex-task-2026-05-10.md`
  - готовая задача/промпт для Codex на другом сервере по доработке `ТЗП`;
  - фиксирует выбранный подход: отдельная внешняя обработка / форк `ТЗП` для
    сборщика от `ЗаказПокупателя`, без нового документа метаданных
    `ЗаданиеНаСборку`.
- `artifacts/site-order-exchange-2026-05-03/`
  - пакет артефактов по обмену заказов сайта и `1С`: SQL-срезы `Заказа
    покупателя`, матрица реквизитов, свойства Bitrix, настройки статусов,
    фрагменты кода `1С` и сайта.
- `Order_Dismantling_Contour_2026-04-02.md`
  - отдельный разбор контура расформирования заказов сайта;
  - связывает задачу `9627` с `10011`, `3966` и `9751`.
- `Transition_Status_Layer_Between_1C_and_B24_2026-04-02.md`
  - фиксирует временное архитектурное решение до перехода на `1С КА`;
  - описывает derived status layer между `1С`, backend и `Bitrix24`.
- `Defect_Quality_Regulation_UT10_3.docx`
  - исходный регламент по браку и контролю качества в `УТ 10.3`;
  - полезен как контекст для задач по приемке, `ОКК`, экспертизам и аналитике брака.
- `Defect_Quality_Contour_2026-04-02.md`
  - предложение по контуру брака и качества;
  - разделяет физическое качество, причину дефекта, кейс `ОКК` и управленческий контроль.
- `Discounted_Goods_Contour_2026-04-02.md`
  - предложение по контуру уцененного товара;
  - фиксирует уценку как отдельный контур продажи после решения по качеству.
- `Expertise_Contour_2026-04-02.md`
  - разбор задачи и чата по экспертизам;
  - фиксирует экспертизу как отдельный кейс, а не просто задачу или запись в журнале `1С`.
- `Return_Reason_Classifier_1C_Project_2026-04-08.md`
  - проект внедрения классификатора причин возврата в `1С`;
  - нужен как источник правил для признака `по вине салона`, KPI и аналитики возвратов.
- `Return_MisSort_1C_TZ_2026-04-27.md`
  - короткое ТЗ на доработку документа `Возврат товаров от покупателя`;
  - фиксирует только 1С-часть: признак несоответствия, фактически принятую номенклатуру, комментарий и проверки.
- `ONEPAGE_Unclaimed_Site_Orders_2026-04-03.md`
  - onepage по незабранным заказам `MASTER-MOBILE.RU`;
  - фиксирует переходный контур `1С events -> derived status -> Bitrix24 CRM / dismantling case`.

Почему папка находится в `pricing-service/docs/`:

- материалы пересекаются с уже существующими документами по логистике, Telegram и внешнему backend-контру;
- содержимое ближе к операционному order/logistics-потоку, чем к `mm-compensation` или `mastermobile`;
- здесь проще использовать эти документы как контекст для будущих техдизайнов и API/бот-проработки.
