# Артефакты обмена заказов сайта и 1С

Дата сбора: `2026-05-03`

Назначение: подтвердить, какие поля и статусы участвуют в цепочке
`сайт -> 1С УТ 10.3 -> сайт`, и почему сайт получает ранний статус
`F = Выполнен` при преждевременной `РТУ` в `1С`.

Сервер интернет-магазина: `87.242.110.232` (`server.master-mobile.ru`).
Интернет-магазин и Bitrix/CRM-механики находятся в одном Bitrix-контуре.

## Ключевой вывод

Для заказа `214840` сайт создал заказ со штатным начальным статусом `N`, а
`2026-05-03 14:51:58` обратный импорт из `1С` пользователем `1C Пользователь`
изменил статус `N -> F` и добавил документ доставки/отгрузки.

Для заказа `211793` обратный импорт из `1С` аналогично изменил статус `P -> F`
`2026-04-16 15:45:59`.

Это подтверждает: сайт получает ложный `Выполнен` из-за того, что `1С`
возвращает событие отгрузки/документ доставки раньше фактической выдачи или
передачи клиенту/ТК.

Параметры `1C_CHANGE_STATUS_FROM_1C` и `1C_FINAL_STATUS_ON_DELIVERY` - это
настройки Bitrix на стороне сайта (`b_option`, модуль `sale`). Они не видны на
форме `1С` `Настройки обмена с WEB-сайтом`.

## Матрица реквизитов

Итоговая матрица подтверждает точные SQL-поля ключевых кастомных реквизитов
`Документ.ЗаказПокупателя`:

- `осиВидОплаты` -> `_Document132._Fld9087RRef` -> `_Reference9084`;
- `осиОплачено` -> `_Document132._Fld9088RRef` -> `_Reference9085`;
- `осиСтатус` -> `_Document132._Fld9092RRef` -> `_Reference9091`;
- `осиСпособДоставки` -> `_Document132._Fld9266`;
- `осиТрекНомер` -> `_Document132._Fld9094`;
- `осиКупон` -> `_Document132._Fld9928`;
- `осиКомКлиента` / клиентское примечание -> `_Document132._Fld9090`.

Главный процессный вывод: старый `осиСтатус` нельзя использовать как
`СтатусИсполнения`, потому что в нем одновременно хранятся типы доставки,
этапы, финалы, ожидание оплаты и коммуникационные состояния.
