## Краткий вывод

`ТЗП` подтвержден как рабочая внешняя обработка, участвующая в сборке и
выдаче/оплате.

Текущая логика `ТЗП` завязана на `РеализацияТоваровУслуг` и сама может
создавать и проводить `РТУ` из `ЗаказПокупателя` до фактической выдачи.

Это подтверждает корневую проблему Wave 1:

```text
сборка / подготовка заказа сейчас может порождать РТУ раньше факта
```

## Структура обработки

После распаковки найдены:

- `ExternalDataProcessor.json` - имя обработки `ТЗП`;
- `Form/Форма/Form.obj.bsl` - основная форма рабочего места;
- `Form/ФормаЗаказов/Form.obj.bsl` - форма поиска/выбора заказов;
- `Form/ФормаР/Form.obj.bsl` - форма создания `РТУ` из заказа;
- `Form/ФормаОплаты/Form.obj.bsl` - форма оплаты/завершения по `РТУ`;
- `Template/Макет*` - печатные/табличные макеты.

## Подтвержденная As-Is логика

### 1. Основная форма показывает реализации как задания на сборку

`Form/Форма/Form.obj.bsl`, процедура `ОтобратьРеал`:

- выбирает `Документ.РеализацияТоваровУслуг`;
- фильтрует по `Подразделение`;
- берет только документы с пустым `осиОтветственный`;
- дополнительно фильтрует ответственного, чей родитель `Сайт`.

В сводной форме тип `2` подписан как `Реализации для сборки`.

### 2. Основная форма также показывает открытые заказы без реализации

В общей выборке есть отдельный блок `Документ.ЗаказПокупателя`.

Условия:

- заказ проведен;
- не помечен на удаление;
- нет связанной `РеализацияТоваровУслуг`;
- нет документа `ЗакрытиеЗаказовПокупателей`;
- дата заказа в пределах последних 14 дней.

Тип `6` в интерфейсе подписан как `Открытые заказы`.

### 3. В форме заказов есть действие `Создать реализацию`

`Form/ФормаЗаказов/Form.obj.bsl`:

- если у заказа нет `РТУ`, в колонке `Реализация` показывается текст
  `Создать реализацию`;
- при выборе действия обработка читает табличную часть
  `ЗаказПокупателя.Товары`;
- проверяет остатки на `Подразделение.осиСклад`;
- делит позиции на `Наличие` и `Отсутствие`;
- открывает `ФормаР`.

### 4. `ФормаР` создает и проводит `РТУ`

`Form/ФормаР/Form.obj.bsl`, процедура `ОсновныеДействияФормыСоздать`:

- создает `Документы.РеализацияТоваровУслуг.СоздатьДокумент()`;
- заполняет склад, контрагента, договор, подразделение, организацию;
- ставит `Реализация.Сделка = Заказ`;
- добавляет строки только по позициям `Наличие`;
- в строках указывает `СтрокаТов.ЗаказПокупателя = Заказ`;
- записывает документ;
- затем пытается провести `РТУ`;
- после этого открывает `Реализация.ПолучитьФорму("ФормаПроверки")`.

Если есть отсутствующие позиции, они добавляются в отдельный
`ЗаказПокупателя` по потребностям.

### 5. Оплата и завершение тоже завязаны на `РТУ`

`Form/ФормаОплаты/Form.obj.bsl`:

- кнопки оплаты создают `ПриходныйКассовыйОрдер` или
  `ОплатаОтПокупателяПлатежнойКартой` через `Заполнить(Реализация)`;
- кнопка `БезОплаты` меняет статус реализации на
  `осиСтатусРеализации.Завершен`;
- форма проверки сканирования также получает `ДокСканирования = Реализация`.

## Что это значит для Wave 1

`ТЗП` надо дорабатывать в Wave 1. Нельзя ограничиться только запретом ручного
создания `РТУ` в форме заказа.

Минимальные изменения:

1. Основную очередь сборки строить от `ЗаказПокупателя`, а не от
   предварительной `РТУ`.
2. В `ФормаЗаказов` заменить действие `Создать реализацию` на действие сборки:
   `В сборку` / `Готов к выдаче` / `Готов к отправке`.
3. В `ФормаР` запретить штатное создание и проведение `РТУ` на этапе сборки.
   Вместо этого фиксировать готовность заказа и проблему отсутствия товара.
4. Логику отсутствующих позиций оставить как разбор потребности, но без
   частичной ранней `РТУ`.
5. Создание `РТУ` разрешить только из отдельного фактического действия:
   `Выдать клиенту` или `Передано в доставку`.
6. `ФормаОплаты` не должна переводить `РТУ` в `Завершен` как способ закрыть
   сборку; оплату и исполнение нужно развести.

## Риск, если не доработать `ТЗП`

Даже если разработчик добавит новые реквизиты заказа и запреты в форме заказа,
пользователь сможет обойти новый процесс через `ТЗП`:

```text
Открытый заказ -> Создать реализацию -> провести РТУ -> сайт получает ложное Выполнен
```

Поэтому приемка Wave 1 должна отдельно проверять `ТЗП`.
