# Wave 1 UT 10.3: диагностика синхронизации общего модуля

Дата: `2026-05-06`  
Контур: `Ekama_Test_Arsen`  
Статус: диагностика блокера, не финальная приемка

## 1. Зачем документ

После handoff по Wave 1 оставался блокер при проведении `РТУ`:

```text
Метод объекта не обнаружен (осиWave1_ПроверитьРТУИнтернетЗаказа)
```

Цель этой проверки - отделить уже перенесенные метаданные Wave 1 от
неподтвержденного состояния общего модуля `осиПривилегированный`.

Вывод: локальная `.local/1c-config` - старый/исходный срез, а не источник для
переноса Wave 1.

## 3. Что подтверждено в SQL-базе `Ekama_Test_Arsen`

Через настроенный read-only SQL-доступ к тестовой 1С-базе проверен слой данных

У таблицы `Документ.ЗаказПокупателя` (`dbo._Document132`) подтверждены 5 новых
колонок Wave 1:

| --- | --- |
| `_Fld10083RRef` | `СтатусИсполнения` |
| `_Fld10084RRef` | `СпособДоставки` |
| `_Fld10085` | `ДатаПередачиВТК` |
| `_Fld10086` | `ПереданоБезТрека` |
| `_Fld10087` | `ПричинаПередачиБезТрека` |

Подтверждены новые справочники:

| SQL-таблица | Справочник | Значения |
| --- | --- | --- |
| `_Reference10081` | `СтатусыИсполненияИнтернетЗаказов` | `Новый`, `Подтвержден`, `На обеспечении`, `Сборка`, `Готов к выдаче`, `Готов к отправке`, `Частично выдан`, `Выдан`, `Отправлен`, `Отменен`, `Проблема / Ручной разбор` |

По тестовым заказам из отчета SQL подтверждает, что старый `осиСтатус` пустой,
а новые поля заполнены:

| Заказ 1С | Raw-доставка | СтатусИсполнения | СпособДоставки | Старый `осиСтатус` |
| --- | --- | --- | --- | --- |
| `РБГУ0033855` | `Самовывоз` | `Новый` | `Самовывоз` | пустой |
| `РБГУ0033856` | `СДЭК (Самовывоз)` | `Отправлен` | `СДЭК` | пустой |
| `РБГУ0033857` | `Почта России (Доставка в отделение)` | `Отправлен` | `Почта` | пустой |
| `РБГУ0033858` | `Доставка курьером` | `Отправлен` | `Курьер` | пустой |

Важно: статусы `Отправлен` у части тестовых заказов в SQL фиксируют текущее
состояние базы на момент проверки. Их нужно интерпретировать вместе с журналом
ручных действий приемки, а не как самостоятельное доказательство зеленого
сценария `РТУ`.

## 4. Что не удалось подтвердить через SQL

Наличие экспортной функции:

```text
осиWave1_ПроверитьРТУИнтернетЗаказа(...) Экспорт
```

в общем модуле `осиПривилегированный` через SQL надежно проверить нельзя.

Причина: код общих модулей хранится в конфигурационном хранилище 1С, а не в
обычных прикладных таблицах. Бинарный поиск строки по таблицам `Config` /
`ConfigSave` не дал совпадений ни по новой функции, ни по старому helper
`ЕстьПроверкаРТУ`, что указывает на упаковку/кодирование конфигурации, а не на
отсутствие кода как факт.

## 5. Текущий диагноз

Метаданные Wave 1 в тестовой базе `Ekama_Test_Arsen` перенесены.

Блокер по `РТУ` остается именно в зоне синхронизации кода конфигурации:

- нужно открыть тестовую базу в конфигураторе или выгрузить актуальный модуль
  `осиПривилегированный`;
- убедиться, что в модуле есть
  `осиWave1_ПроверитьРТУИнтернетЗаказа(...) Экспорт`;
- если функции нет - перенести актуальный общий модуль из рабочей копии другого
  сервера;
- если функция есть - перезапустить клиентскую сессию 1С и повторить проведение
  `РТУ`, потому что ошибка может быть следствием старой сессии/неперечитанной
  конфигурации.

Отдельно: локальный wrapper `scripts/with_onec_test.sh` по умолчанию уводит
проверки в базу `Ekama_Test`, а не в `Ekama_Test_Arsen`. Для диагностик Wave 1
нужно явно использовать `Ekama_Test_Arsen`.

## 6. Следующий приемочный шаг

После подтверждения/переноса `осиПривилегированный` повторить сценарии `РТУ`:

1. Самовывоз из `Новый` должен блокироваться сообщением:

   ```text
   Wave 1: РТУ самовывоза разрешена только из статуса Готов к выдаче или Частично выдан.
   ```

2. Самовывоз из `Готов к выдаче` должен проводиться и ставить `Выдан` либо
   `Частично выдан`.
3. `СДЭК` / `Почта` без `ДатаПередачиВТК` и трека должны блокироваться.
4. `СДЭК` / `Почта` с датой передачи и треком должны проводиться и ставить
   `Отправлен`.
5. `Курьер` / `Такси` без даты передачи должны блокироваться.
6. `Курьер` / `Такси` с датой передачи должны проводиться без обязательного
   трека и ставить `Отправлен`.

После зеленого прогона обновить
`docs/order_flow/ut103-site-order-wave1-work-report-2026-05-06.md`.
