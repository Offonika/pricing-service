# Wave 1 UT 10.3: отчет о выполненных работах и тестах

Дата отчета: `2026-05-06`

Контур: `УТ 10.3.11.4`, платформа `1С 8.2.19.130`, тестовая база
`Ekama_Test_Arsen`.

## 1. Цель этапа

Проверить и довести комплект Wave 1 для интернет-заказов до рабочего состояния
на тестовой базе:

```text
РТУ = только факт выдачи клиенту или передачи в ТК/курьеру/такси
```

Локально в репозитории хранится комплект переноса модулей и проектная
документация. Живая проверка выполнялась в удаленной тестовой базе.

## 2. Что реализовано

### Метаданные

В тестовой базе подготовлены объекты Wave 1:

- справочник `СтатусыИсполненияИнтернетЗаказов`;
- справочник `СпособыДоставкиИнтернетЗаказов`;
- реквизиты `Документ.ЗаказПокупателя`:
  - `СтатусИсполнения`;
  - `СпособДоставки`;
  - `ДатаПередачиВТК`;
  - `ПереданоБезТрека`;
  - `ПричинаПередачиБезТрека`;
- регистр сведений `осиWave1АварийныеРТУБезТрека`;
- поля на форме заказа для новых реквизитов, raw-доставки и трека.

### Обмен с сайтом

Доработан модуль `Обработка.ОбменССайтом`:

- raw-доставка сайта пишется в `осиСпособДоставки`;
- нормализованная доставка пишется в `СпособДоставки`;
- новый интернет-заказ получает `СтатусИсполнения = Новый`;
- доставка больше не записывается в старый `осиСтатус`;
- оплата остается в оплатных реквизитах и не меняет `СтатусИсполнения`;
- повторная загрузка не должна затирать Wave 1-факты:
  `СтатусИсполнения`, `ДатаПередачиВТК`, `ПереданоБезТрека`,
  `ПричинаПередачиБезТрека`;
- убраны клиент-серверные ошибки 1С 8.2 от передачи мутабельного
  `ДокументОбъект` в серверный общий модуль.

### Проверка РТУ

Доработан модуль `Документ.РеализацияТоваровУслуг`:

- проверка Wave 1 запускается до формирования движений;
- РТУ проверяется по ссылке документа, без передачи `ЭтотОбъект` в серверный
  общий модуль;
- после проведения РТУ заказ должен получить итоговый статус:
  - `Выдан` / `Частично выдан` для самовывоза;
  - `Отправлен` для доставок;
- аварийная ТК без трека должна писать аудит;
- техническая ранняя РТУ после перемещения для интернет-заказа запрещается;
- убран вызов отсутствующего в тестовой базе helper-метода
  `осиПривилегированный.ЕстьПроверкаРТУ`, заменен безопасной проверкой
  `Основание.Подразделение.осиПроверкаРТУ`.

### Документация

Добавлены и обновлены документы:

- `docs/order_flow/ut103-site-order-wave1-implementation-2026-05-03.md`;
- `docs/order_flow/ut103-site-order-wave1-remote-install-checklist-2026-05-03.md`;
- `docs/order_flow/ut103-site-order-wave1-control-reports-2026-05-03.md`;
- `docs/order_flow/ut103-site-order-wave1-testing-task-2026-05-04.md`;
- `docs/order_flow/ut103-site-order-wave1-production-install-instruction.md`.

В документации зафиксировано правило сопровождения: новые ошибки сначала
оформляются как диагноз, причина, план, риск и проверка. Код, метаданные и
настройки обмена менять только после явного разрешения владельца задачи.

## 3. Локальные проверки

Запускался статический тест:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File migration/ut103/tests/Test-Wave1Static.ps1
```

Результат последнего запуска:

```text

```

Статический тест проверяет:

- новый статус ставится только новым заказам;
- Wave 1-реквизиты не затираются при обновлении старого заказа;
- доставка сохраняется raw и нормализуется;

- техническая РТУ после перемещения блокируется;
- документы содержат инструкции по тестовой базе и переносу.

## 5. Проверки РТУ

### Самовывоз

Проверялся сценарий:

```text
СпособДоставки = Самовывоз
СтатусИсполнения = Новый
```

Ожидаемое поведение:

```text
РТУ из статуса Новый блокируется
```

В ходе проверки были выявлены технические проблемы синхронизации модулей:

- `Метод объекта не обнаружен (осиWave1_ПроверитьРТУИнтернетЗаказа)` -
  общий модуль в тестовой базе не был обновлен или не был перечитан сессией;
- ранее была ошибка передачи мутабельного объекта с клиента на сервер -
  исправлена переходом на передачу `Ссылка`.

После корректного переноса общего модуля ожидаемое сообщение блокировки:

```text
Wave 1: РТУ самовывоза разрешена только из статуса Готов к выдаче или Частично выдан.
```

### Курьер / Такси

Получено ожидаемое сообщение проверки:

```text
Wave 1: для Курьер/Такси перед РТУ нужен факт физической передачи.
```

Правило подтверждено: для `Курьер` / `Такси` перед проведением РТУ нужно
заполнить в заказе `ДатаПередачиВТК`. Трек для этих способов доставки не
обязателен.

### Договор контрагента

При создании/записи РТУ была выявлена старая проверка формы:

```text
Договор ... не является Основным договором контрагента ...
```

Диагноз:

- это не часть Wave 1;
- старая форма РТУ сравнивает ссылку `ДоговорКонтрагента` с
  `Контрагент.ОсновнойДоговорКонтрагента`;
- одинаковое наименование договора не гарантирует одинаковую ссылку;
- правки выбора договора не вносились в Wave 1 после обсуждения.

Вопрос договора вынесен отдельно: нужно отдельно согласовать правило выбора
договора интернет-заказа при нескольких договорах контрагента.

## 6. Выявленные и исправленные проблемы

| Проблема | Статус |
| --- | --- |
| HTTPS обмена не работает на `1С 8.2.19.130` из-за SSL | для теста используется HTTP |
| Сайт отдавал слишком большой пакет заказов, 1С падала по памяти | очередь обмена ограничена/очищена для теста |
| Передача `ДокументОбъект` в серверный общий модуль вызывала ошибку 8.2 | исправлено |
| `СпособДоставки` не заполнялся из raw `Самовывоз` | исправлено |
| `ЕстьПроверкаРТУ` не найден в тестовой базе | вызов убран из модуля РТУ |
| `осиWave1_ПроверитьРТУИнтернетЗаказа` не найден при проведении | требуется проверить перенос общего модуля в тестовой базе |
| Проверка основного договора мешает РТУ | не Wave 1, вынесено отдельно |

## 7. Открытые вопросы

- Убедиться, что в тестовой базе актуально перенесен общий модуль
  `осиПривилегированный` и функция
  `осиWave1_ПроверитьРТУИнтернетЗаказа(...) Экспорт` реально есть в
  конфигурации базы данных.
- Завершить приемочные тесты РТУ после синхронизации общего модуля:
  самовывоз, СДЭК/Почта, Курьер/Такси, частичная выдача.
- Отдельно согласовать правило выбора договора интернет-заказа при нескольких
  договорах контрагента.
- Для боевого обмена решить технический вопрос HTTPS/TLS для платформы 8.2:
  HTTP допустим только как тестовое временное решение.

## 8. Текущий вывод

Контур загрузки интернет-заказов с тестового сайта в УТ 10.3 работает:

- заказы создаются;
- доставка raw сохраняется;
- нормализованная доставка заполняется;
- статус исполнения ставится `Новый`;
- старый `осиСтатус` не используется как доставка.

Контур РТУ частично проверен, но требует финальной синхронизации общего модуля
в тестовой базе и повторного прогона приемочных сценариев.
