# Контекст для нового чата: Wave 1 UT 10.3 интернет-заказы

Дата фиксации: `2026-05-06`

## 1. Коротко

Продолжаем разработку Wave 1 для интернет-заказов в `1С УТ 10.3`.

Главное правило процесса:

```text
РТУ = только факт выдачи клиенту или передачи в ТК/курьеру/такси
```

Цель Wave 1: убрать ранние/технические `РТУ`, не писать доставку и оплату в
старый `осиСтатус`, хранить этап исполнения отдельно, а сайт не должен получать
ложный статус `Выполнен` раньше факта.

## 3. Фактическое состояние на 2026-05-06

Тестовая база:

- `Ekama_Test_Arsen`

Контур:

- `УТ 10.3.11.4`
- платформа `1С 8.2.19.130`

В тестовой базе подготовлены:

- справочник `СтатусыИсполненияИнтернетЗаказов`;
- справочник `СпособыДоставкиИнтернетЗаказов`;
- реквизиты `Документ.ЗаказПокупателя`:
  - `СтатусИсполнения`;
  - `СпособДоставки`;
  - `ДатаПередачиВТК`;
  - `ПереданоБезТрека`;
  - `ПричинаПередачиБезТрека`;
- регистр сведений `осиWave1АварийныеРТУБезТрека`;
- поля на форме заказа для новых реквизитов, raw-доставки и трека.

Доработан обмен с сайтом:

- raw-доставка сайта пишется в `осиСпособДоставки`;
- нормализованная доставка пишется в `СпособДоставки`;
- новый интернет-заказ получает `СтатусИсполнения = Новый`;
- доставка больше не записывается в старый `осиСтатус`;
- оплата не меняет `СтатусИсполнения`;
- повторная загрузка не должна затирать Wave 1-факты:
  `СтатусИсполнения`, `ДатаПередачиВТК`, `ПереданоБезТрека`,
  `ПричинаПередачиБезТрека`;
- исправлены ошибки 1С 8.2 от передачи мутабельного `ДокументОбъект` в
  серверный общий модуль.

Доработана проверка `РТУ`:

- проверка Wave 1 запускается до формирования движений;
- `РТУ` проверяется по ссылке документа, без передачи `ЭтотОбъект`;
- после проведения `РТУ` заказ должен получить:
  - `Выдан` / `Частично выдан` для самовывоза;
  - `Отправлен` для доставок;
- аварийная ТК без трека должна писать аудит;
- техническая ранняя `РТУ` после перемещения для интернет-заказа запрещается;
- вызов отсутствующего helper-метода `осиПривилегированный.ЕстьПроверкаРТУ`
  убран, заменен проверкой `Основание.Подразделение.осиПроверкаРТУ`.

## 5. Текущий блокер

Контур `РТУ` проверен частично.

Блокер:

```text
Метод объекта не обнаружен (осиWave1_ПроверитьРТУИнтернетЗаказа)
```

Диагноз из отчета:

- общий модуль в тестовой базе не был обновлен или не был перечитан сессией;
- нужно убедиться, что в тестовой базе актуально перенесен общий модуль
  `осиПривилегированный`;
- функция `осиWave1_ПроверитьРТУИнтернетЗаказа(...) Экспорт` реально должна
  быть в конфигурации базы данных.

После корректного переноса общего модуля ожидаемое сообщение для самовывоза из
статуса `Новый`:

```text
Wave 1: РТУ самовывоза разрешена только из статуса Готов к выдаче или Частично выдан.
```

Проверка `Курьер` / `Такси` уже дала ожидаемое сообщение:

```text
Wave 1: для Курьер/Такси перед РТУ нужен факт физической передачи.
```

## 6. Открытые вопросы

1. Синхронизировать комплект переноса/тестов из рабочей копии на другом
   сервере в текущий workspace или определить, какой сервер является актуальным
   источником файлов.
2. Убедиться, что `осиПривилегированный` в тестовой базе содержит экспортную
   функцию `осиWave1_ПроверитьРТУИнтернетЗаказа(...)`.
3. Завершить приемочные тесты `РТУ`:
   - самовывоз;
   - `СДЭК` / `Почта`;
   - `Курьер` / `Такси`;
   - частичная выдача.
4. Отдельно согласовать правило выбора договора интернет-заказа при нескольких
   договорах контрагента.
5. Для боевого обмена решить вопрос HTTPS/TLS для платформы `1С 8.2.19.130`.
   HTTP допустим только как тестовое временное решение.
6. Отдельно продолжить доработку `ТЗП`: сборка должна идти от
   `ЗаказПокупателя`, а не от предварительной `РТУ`.
