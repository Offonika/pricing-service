# Смарт-процесс «Формирование заказа»

Статус: implemented, pilot disabled.

## Граница ответственности

- `pricing-service` хранит заказ, строки, версии, блокеры и согласования.
- Bitrix24 показывает одну карточку на один будущий `ЗаказПоставщику` и стандартные товарные строки.
- Товар связывается только по `XML_ID = GUID номенклатуры 1С`; поиск по названию и артикулу запрещён.
- 1С получает только `draft_only=true`; автоматическое проведение не реализовано.
- Розничная цена каталога не читается и не изменяется. Закупочная цена живёт в строке заказа.

## Стадии

1. `Черновик сформирован`.
2. `На проверке`.
3. `Согласовано к 1С`.
4. `Передача в 1С`.
5. `Передано в 1С`.
6. Финалы: `Отложено / отменено`, `Ошибка передачи`.

В Bitrix24 системная семантика неуспешного финала назначена стадии `Отложено / отменено`. `Ошибка передачи` остаётся отдельной закрывающей бизнес-стадией перед системными финалами, потому что портал не разрешает создать второй failure-финал универсального процесса.

Любое изменение условий, количества, цены, состава или согласованной классификации увеличивает версию заказа и снимает согласование.

## Классификация строки

Ручные статусы: `Рабочий`, `Матричный`, `Под заказ`, `Кандидат на замену`, `Кандидат на неликвид`, `Не закупать`.

`Не закупать`, `Кандидат на замену`, `Кандидат на неликвид` блокируют строку. `Под заказ` блокирует автоматическую потребность и разрешается только при `explicit_demand=true`.

Предложение классификации хранится отдельно от заказа. Для него обязательна причина; при ручном минимуме обязательна дата пересмотра. Утверждать могут только Bitrix-пользователи из `PROCUREMENT_ORDER_FORMATION_CLASSIFICATION_APPROVER_USER_IDS`.

После утверждения строится `nomenclature_property_updates.v1` с ожидаемым текущим статусом. Запись в 1С включается только флагом `PROCUREMENT_ORDER_FORMATION_PROPERTY_APPLY_ENABLED=true`. После результата 1С выполняется readback каталога Bitrix по `XML_ID`.

## Безопасный запуск

```bash
./.venv/bin/python scripts/ensure_order_formation_bitrix_process.py
./.venv/bin/python -m tasks.build_procurement_order_formation_dry_run --json
```

Первая команда создаёт только локальный mapping-план. Вторая формирует JSON/CSV без записи в Bitrix и 1С.

Создание процесса после проверки:

```bash
./.venv/bin/python scripts/ensure_order_formation_bitrix_process.py --apply
```

Пилотные черновики в БД создаются отдельным `--persist-db`; карточки Bitrix и сообщения 1С этим флагом не создаются. Передача заказа в 1С дополнительно защищена `PROCUREMENT_ORDER_FORMATION_ONEC_APPLY_ENABLED=false`.

## Основные файлы

- `app/models/procurement_order_formation.py` — состояние и история согласований.
- `app/services/procurement_order_formation.py` — версии, блокеры и XML-контракты.
- `app/services/bitrix_order_formation.py` — GUID-сопоставление и товарные строки Bitrix.
- `app/api/procurement_order_formation.py` — API встроенного интерфейса.
- `ui/src/components/ProcurementOrderFormationApp.tsx` — пакетный заказ и классификация строки.
- `tasks/build_procurement_order_formation_dry_run.py` — группировка текущего расчёта.
- `tasks/sync_procurement_order_formation_results.py` — результат 1С и CommerceML-readback.
