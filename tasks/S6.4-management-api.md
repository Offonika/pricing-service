# S6.4 — Поднять приватный API Management Control Tower для сервера B

## Цель
Открыть на сервере `A` приватный API, через который `Openclaw` на сервере `B` сможет забирать готовые управленческие витрины без прямого доступа к БД.

## Что нужно сделать
- Добавить endpoint'ы:
  - `GET /api/management/digests/morning`
  - `GET /api/staffing/daily`
  - `GET /api/staffing/period-summary`
  - `GET /api/receivables/new-daily`
  - `GET /api/receivables/cases`
  - `GET /api/receivables/manager-summary`
  - `GET /api/receivables/employee-cases`
- Ввести service-to-service аутентификацию для `B`.
- Добавить Pydantic-схемы ответов и стандарт ошибок.
- Ограничить API read-only режимом.
- Реализовать интеграционные тесты по ключевым endpoint'ам.
- Задокументировать контракт для команды `Openclaw`.

## Артефакты/файлы
- `app/api/management/*`
- `app/api/staffing/*`
- `app/api/receivables/*`
- `app/schemas/*`
- тесты API
- документация по контракту

## Definition of Done
- Сервер `B` может авторизованно читать management-данные по HTTP API.
- Контракты API стабильны и задокументированы.
- Неполные данные возвращают предсказуемый статус/флаг свежести.
- Есть интеграционные тесты на happy path и основные ошибки доступа.
