# Дозаполнение статьи ДДС для эквайринга

Внешняя обработка для ситуации, когда старая загрузка `Клиент-Банк` уже создала
документы `ПлатежноеПоручениеВходящее`, но в строках `РасшифровкаПлатежа`
осталась пустая статья ДДС.

Обработка не зависит от `КлиентБанк` / `КлиентБанк1`: её запускают отдельно
после загрузки выписки. Она ищет входящие платежные поручения за период с видом
операции `Поступление оплаты по платежным картам` и ставит статью:

`Оплата от покупателя (за товар)`

## Состав

- `bank_acquiring_dds_postfill_object_module.bsl` - модуль объекта внешней обработки.
- `bank_acquiring_dds_postfill_form_module.bsl` - модуль основной формы.

## Как собрать EPF

1. В конфигураторе 1С создать новую внешнюю обработку.
2. В модуль объекта вставить `bank_acquiring_dds_postfill_object_module.bsl`.
3. Создать основную форму.
4. Добавить реквизиты формы:
   - `ДатаНачала` - дата;
   - `ДатаОкончания` - дата;
   - `НаименованиеСтатьиДДС` - строка;
   - `ФайлЛога` - строка;
   - `ТолькоПроверка` - булево, по умолчанию `Истина`;
   - `ПерепроводитьПроведенные` - булево, по умолчанию `Истина`;
   - `МаксимумДокументов` - число, `0` означает без ограничения.
5. Добавить поля для реквизитов и две кнопки:
   - выбор файла лога, обработчик `ВыбратьФайлЛогаНажатие`;
   - выполнение, обработчик `ВыполнитьНажатие`.
6. В модуль формы вставить `bank_acquiring_dds_postfill_form_module.bsl`.

## Рекомендуемый запуск

1. Сделать копию базы или хотя бы выгрузку перед боевым прогоном.
2. Поставить период, например `01.05.2026` - `10.05.2026`.
3. Запустить с `ТолькоПроверка = Истина`.
4. Проверить CSV-лог: должны быть `DRY_RUN` или `ALREADY_OK`, без `ERROR_*`.
5. Снять `ТолькоПроверка` и запустить боевой режим.

Если документ проведен, при включенном `ПерепроводитьПроведенные` обработка
сохранит его с режимом проведения. Если перепроведение выключено, проведенные
документы будут пропущены.
