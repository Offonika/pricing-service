# Исправление РТУ: НДС в том числе

Внешняя обработка для списка `reports/vat_top_sales_TO_FIX.xlsx`. Также поддерживает парный CSV `reports/vat_top_sales_TO_FIX.csv`; CSV и XLSX содержат только документы, где в SQL-выгрузке `_Fld4945 = 0x01`, `_Fld4946 = 0x00` и есть сумма НДС сверху.

Текущий список `vat_top_sales_TO_FIX.*` обновлен по задаче Bitrix `#275`: из
первоначальных 306 строк исключены `ИП Терехин` и `Мастер ТЦА` по сообщению в
чате задачи от 2026-05-23. В рабочем списке осталось 101 строка.

Исходный широкий список `reports/vat_top_sales_FINAL.*` оставлен для аудита. В него попали не только документы на исправление, но и РТУ с отключенным учетом НДС (`_Fld4945 = 0x00`); такие строки обработка пропускает как `SKIP_FILE_NO_VAT_ACCOUNTING`.

Задача: для документов `РеализацияТоваровУслуг` из рабочего списка заменить ошибочный режим `НДС сверху` на `НДС в том числе` и уменьшить итоговую сумму документа на ошибочно начисленный НДС сверху. Обработка ставит флаг `СуммаВключаетНДС`, пересчитывает `СуммаНДС` как включенный НДС и перепроводит документ.

Документ ищется по номеру и дате из файла; `СсылкаДокументаHex` используется только как дополнительная подсказка при дублях. Если ссылка из SQL-выгрузки не совпала с представлением ссылки в 1С, но номер, дата и сумма однозначно нашли документ, обработка не блокирует исправление.

## Состав

- `vat_included_fix_object_module.bsl` - модуль объекта внешней обработки.
- `vat_included_fix_form_module.bsl` - модуль основной формы.

## Как собрать EPF

Если при открытии готового файла появляется ошибка `Неверный формат хранилища данных`,
значит платформа не смогла прочитать сам `.epf`. Это не ошибка расчета НДС. Обычно
так бывает, если файл поврежден, скачался не полностью или был сохранен в другой
версии платформы. Для `УТ 10.3` обработку нужно собрать и сохранить именно в
конфигураторе `1С 8.2`, а не в `8.3`.

1. В конфигураторе 1С создать новую внешнюю обработку.
2. В модуль объекта вставить `vat_included_fix_object_module.bsl`.
3. Создать основную форму.
4. Добавить реквизиты формы:
   - `ФайлСписка` - строка;
   - `ФайлЛога` - строка;
   - `ТолькоПроверка` - булево, по умолчанию `Истина`;
   - `ПерепроводитьПроведенные` - булево, по умолчанию `Истина`;
   - `КонтролироватьСумму` - булево, по умолчанию `Истина`;
   - `ДопустимоеОтклонение` - число, по умолчанию `0.05`;
   - `МаксимумДокументов` - число, `0` означает без ограничения;
   - `ОбрабатыватьНепроведенные` - булево, по умолчанию `Ложь`.
5. Добавить поля для реквизитов и три кнопки:
   - выбор файла списка, обработчик `ВыбратьФайлСпискаНажатие`;
   - выбор файла лога, обработчик `ВыбратьФайлЛогаНажатие`;
   - выполнение, обработчик `ВыполнитьНажатие`.
6. В модуль формы вставить `vat_included_fix_form_module.bsl`.

## Рекомендуемый запуск

1. Сделать архивную копию базы.
2. Выбрать именно `vat_top_sales_TO_FIX.xlsx` или сверенный `vat_top_sales_TO_FIX.csv`; `vat_top_sales_FINAL.*` использовать только для аудита, старый `vat_top_sales_2025-09_to_2026-04.*` не использовать.
3. Запустить обработку с `ТолькоПроверка = Истина` и `МаксимумДокументов = 10`.
4. Проверить лог: статусы должны быть `DRY_RUN`, `ALREADY_OK` или ожидаемые `SKIP_*`, без `ERROR_*`.
   `DRY_RUN` уже выполняет конвертацию документа в памяти и проверяет, что
   итоговая сумма стала равна `СуммаДокумента - НДСВсегоСверху`; запись и
   проведение при этом не выполняются.
5. Запустить dry-run без ограничения и сверить количество `КИсправлению`; для текущего `vat_top_sales_TO_FIX.*` ожидается 101 строка.
6. Выключить `ТолькоПроверка` и выполнить боевой прогон.
7. После выполнения повторить контрольную SQL/выгрузку: список проблемных документов должен стать пустым.

## Лог

Лог пишется в CSV со статусами:

- `DRY_RUN` - документ найден и будет исправлен в боевом режиме.
- `OK` - документ исправлен.
- `ALREADY_OK` - документ уже был в режиме `НДС в том числе`.
- `SKIP_*` - документ пропущен по контролю.
  `SKIP_FILE_NO_VAT_ACCOUNTING` означает, что в файле у документа отключен
  учет НДС (`_Fld4945 <> 0x01`), поэтому обработка не должна переводить его в
  режим `НДС в том числе`.
- `ERROR_*` - документ не исправлен, нужна ручная проверка.
  `ERROR_DRY_RUN` означает, что ошибка найдена ещё на проверочной конвертации
  в памяти.

Лог сбрасывается в файл после каждой строки, чтобы при аварийном завершении
оставался аудит уже проверенных или исправленных документов.

Обработка дополнительно использует `СсылкаДокументаHex` из файла как подсказку
при дублях. Если номер, дата и сумма однозначно нашли документ, несовпадение
SQL-hex с представлением ссылки внутри 1С не блокирует обработку.

CSV читается с учетом кавычек и экранированных кавычек, поэтому пересохранение
файла с `;` внутри текстовых колонок не должно сдвигать первые контрольные поля.

Для боевого запуска нужен пользователь с правами записи и перепроведения старых проведенных РТУ. В текущей конфигурации модуль документа запрещает изменение проведенных документов без полных прав.
